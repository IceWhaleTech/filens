# filens 通俗介绍与测试指南

这份说明写给不需要了解 WASM、文件协议或渲染引擎的同事。你只要平时会打开文档、图片、图纸或模型，就可以理解和参与测试。

## 一句话介绍

filens 是一个“让应用自己读懂文件”的开源项目，核心能力可以运行在任何能够集成 WASM 的环境里。

通常，网页要预览一个复杂文件，会先把文件上传到服务器，再由服务器安装的 Office、转换器或专业软件把它变成图片、PDF 或 HTML。filens 希望尽可能把这件事放到用户自己的电脑和浏览器里完成：文件选择后就地解析、就地显示，不必先排队上传和等待服务器转换。但浏览器只是最直接的一种使用方式；桌面与移动客户端、CLI、边缘节点和后端服务也可以通过 WASM/WASI 宿主复用同一套解析与转换核心。

名字也可以从两个角度理解：

- **File Lens**：像镜头一样看见文件里的内容。
- **File Native Services**：把不同文件格式的原生能力提供给应用和 AI Agent 使用。

## 它能用在哪里

- 网盘、NAS、知识库里的文件预览
- 文件列表中的封面和缩略图
- 全文检索前的文本和元数据提取
- 扫描件接入 OCR 后的内容搜索
- AI Agent 读取、检查和理解用户提供的文件
- 不方便上传到云端的私密或大型文件查看
- 浏览器中查看 CAD 图纸、全景照片、RAW 和 3D 模型
- 在桌面端、移动端、CLI、边缘节点或自建服务中批量提取文本、生成缩略图和建立索引

## 为什么 WASM 与纯端侧方案很重要

### 打开更快

支持的文件可以在本地直接处理，省去“上传文件 -> 服务器排队 -> 转换 -> 下载结果”这一整段等待时间。对于局域网、NAS、边缘设备和弱网环境，这个差别尤其明显。

### 更保护隐私

合同、设计稿、财务表格、个人照片等文件不必为了预览而离开设备。是否上传、是否接入云端服务，可以由产品自己决定，而不是预览功能的必选项。

### 更节省服务器

传统预览服务需要 CPU、内存、字体、临时磁盘和转换进程。filens 把能够端侧完成的工作交给客户端或本地 WASM 宿主，可以减少服务器扩容、任务队列和异常文件隔离的压力。

### 更适合 Serverless 和离线场景

预览和转换能力可以作为模块按需加载。应用不需要为了“偶尔打开一个文件”常驻一套重型转换服务，在浏览器、内网、桌面壳、移动端 WebView、CLI 或离线环境中也更容易复用。

### 同一核心也能部署到服务端

端侧优先不等于只能运行在浏览器里。对于需要集中索引、批处理、统一 API、服务端缩略图或 Agent 工具调用的产品，可以在 CLI、边缘函数或后端服务中嵌入兼容的 WASM/WASI 运行时。这样仍然复用同一套转换核心，服务端只负责请求、文件和结果管理，不需要再实现一套格式解析算法。

## 一个 10 MB PPTX，大概会差多少时间

仓库中有一个 11.12 MB、13 页的真实 PPTX 样例。在 Apple M4 Pro 上，从选择文件到第 1 页可见，filens 的 7 次测试中位数为 **91.7 毫秒**；把浏览器 CPU 人为降低 4 倍后，中位数为 **347.9 毫秒**。这个文件带来的 JS Heap 增量约为 **25 MiB**。

其他方案缺少统一硬件、统一文件的公开跑分，因此只能先做容量规划估算：

- filens 原生 PPTX：现代桌面设备可先按 **0.1-0.8 秒**估算。
- LibreOffice/OpenOffice 服务端转换：热进程大约 **2-10 秒**，冷启动、大文件或排队时可能达到 **5-20 秒**。
- Microsoft 365、永中 DCS 等在线方案：100 Mbps 上行时通常仍需预留 **2-10 秒**；国内家宽上行普遍只有约 **10-20 Mbps**，单是上传 10 MiB 文件就大约需要 **5-12 秒**，加上鉴权、排队、转换和结果获取后，总时间可达到 **7-32 秒**。

这些数字比较的是“刚选择一个新文件，到第一次看到内容”。如果在线文件早已上传，或者服务器已经缓存了转换结果，重复打开也可能低于 1 秒。相反，高并发排队、字体加载、复杂动画、视频和超大图片都会让服务端方案变慢。详细假设和可信度标记见[项目详细介绍的方案对比](project-overview.zh-CN.md#10-mb-pptx-首次预览时间估算)。

## filens 厉害在哪里

### 1. PPTX 不是截图，而是原生解析

filens 直接读取 PPTX 中的页面、文字、图片、表格、主题、形状等结构，再通过浏览器的 HTML/SVG 渲染。这样不仅能看，还为后续的搜索、元素定位、选择和 Agent 理解保留了结构信息。

据我们所知，filens 是目前唯一以这一覆盖范围为目标的开源 PPTX 原生预览实现，并在同类浏览器原生方案中保持领先的兼容性。它仍不是 PowerPoint 的完整替代品，动画、复杂图表、嵌入对象和少见形状仍需要持续补齐。

### 2. iWork 可以不经过苹果云端

Keynote、Pages、Numbers 一直缺少成熟的跨平台开源预览方案。常见做法是调用 macOS/iOS 原生组件，或上传到 iCloud 在线转换。ONLYOFFICE 最近加入了相关转换，但对新版本 iWork 文件的兼容性和保真仍有限。

filens 直接解析当前版本的 iWork 协议结构，并在浏览器中预览。早期协议研究与代码基础来自 [`dunhamsteve/iwork`](https://github.com/dunhamsteve/iwork)，项目明确保留这项贡献说明，并在其部分工作之上继续扩展新格式和渲染能力。

### 3. 传统 Office/WPS 转换核心非常小

为了让旧 `.doc`、`.wps` 等文件进入现代预览链路，filens 提供面向预览的 OpenXML 标准化能力。当前核心 Brotli 后约 300 KB，与几十 MB 乃至数百 MB 的传统办公转换组件相比非常轻量。

这里追求的是“快速打开、提取和降级预览”，不是一比一重建所有排版、公式、图表、动画和宏。需要生产级高保真转换时，仍应使用更重的专业引擎。

### 4. CAD 既有转换积累，也有纯浏览器路径

CAD 转换部分来源于 [`orcastor/cad2x-converter`](https://github.com/orcastor/cad2x-converter)。cad2x 是一个经过大幅裁剪的 DXF/DWG 转换工具，可以输出 DXF、PDF、PNG 和 SVG，并处理字体、编码、纸张和缩放等实际问题。

filens 进一步实现了 DXF 的纯浏览器解析和 SVG 渲染。对于支持的二维图纸，不需要启动桌面 CAD 软件，也不需要把文件发到转换服务器，就能查看常见线条、圆弧、样条、填充、文字、块、尺寸、图层、颜色和线型。DWG 等更复杂路径仍可按需接入 cad2x 风格的转换方案。

### 5. 不只预览办公文档

filens 还覆盖许多普通在线文档预览器不会处理的格式：

- 360° 全景照片和部分相机原始全景格式
- 多种相机 RAW 和 ICNS 图标
- STEP/STP、STL、OBJ、PLY、glTF/GLB、3MF 等 3D/CAD 格式
- 点云、体素、分子、动作骨骼和体数据
- EPUB/CBZ、压缩包、思维导图和流程图

这些能力共享同一个预览容器，但按需加载各自模块，不会要求所有用户一次下载全部功能。

### 6. 同一套能力还可以给客户端、服务端和 Agent 使用

浏览器预览只是入口。相同的文件理解能力还可以用于桌面与移动客户端、命令行、边缘节点、后端服务和 AI Agent，例如：检查文件类型、提取文字、生成缩略图、读取元数据、识别文件中的页和元素，并返回结构化结果。

统一 Agent CLI 仍在建设中；当前仓库已经有 WASM 转换核心和 Go/wazero CLI 示例。

## 它是怎么工作的

可以把 filens 理解成两类处理路径：

```text
文件
 |
 +-- 宿主能直接预览 -----------> 原生预览适配和渲染
 |
 +-- 需要整理成中间格式 --------> 按需加载 WASM
                                      |
                                      +--> 文本、图片、图标、元数据
                                      +--> 面向预览的 OpenXML 标准化

最终结果可以交给网页、桌面/移动客户端、CLI、服务端、边缘节点或 AI Agent。
```

后端如果需要调用转换，也只是给同一个 WASM 核心套一层很薄的 CLI/HTTP 外壳，不再维护第二套格式转换算法。

## 接下来还要做什么

- 搜索到一句话后，能够跳回具体页、幻灯片、工作表或某个元素并高亮定位
- 支持 HLS 等视频流、可选转码、更完整的时间轴和全景视频预览
- 支持受密码保护的 Office/WPS、PDF 等文档，在端侧安全输入密码并本地解密，或由受控 WASM 宿主提供凭据；默认不把密码暴露在参数、日志或结果中
- 按需引入更多常用拉丁、CJK、Emoji、数学符号和 CAD SHX 字体，完善缺失字体检测、替换提示、子集化与缓存，同时保持核心产物轻量
- 完善 Agent CLI，让 Agent 稳定完成检查、提取、渲染、缩略图和文件理解
- 持续提升 PPTX、iWork、CAD、全景和各种真实文件的兼容性

## 邀请大家帮忙测试

文件格式的复杂度主要藏在真实文件里。自动生成的小样例可以验证基本功能，但找不出所有字体、排版、编码、相机、软件版本和历史兼容问题。大家日常工作中遇到的文件，反而是最有价值的测试集。

如果你愿意帮忙，不需要研究代码。选择一个可以安全测试的真实文件，打开后检查下面几项即可。

### 不要只看“能不能打开”

- **内容**：页数、文字、图片、表格、图层或模型零件是否缺失
- **位置**：文字、形状、图片、尺寸线是否错位或超出页面
- **样式**：字体、字号、颜色、线型、透明度、背景是否明显不对
- **交互**：翻页、缩放、旋转、图层开关、模型选择等操作是否正常
- **性能**：首次打开是否过慢，操作是否卡顿，内存是否持续上涨
- **降级提示**：不支持的内容是否有明确警告，而不是静默消失

### 建议优先测试的文件

- 使用 WPS 或较老 Office 保存的 `.doc`、`.wps`、`.xls`、`.ppt`
- 包含复杂母版、表格、组合形状、特殊字体的 PPTX
- 最新版 Keynote、Pages、Numbers 以及多年以前保存的 iWork 文件
- 包含中文、SHX 字体、块、填充、尺寸、外部图片和多个图层的 DXF
- 来自不同相机品牌的 RAW、全景照片或视频
- 带外部贴图、多个零件或较大数据量的 3D 模型
- 文件名、路径或内容中包含中文、空格和特殊字符的文件

## 怎样记录一个有用的问题

请提交到 [GitHub Issues](https://github.com/IceWhaleTech/filens/issues/new/choose)。一个容易复现的问题通常包含：

1. **文件类型**：例如 PPTX、KEY、DXF、CR3、GLB。
2. **文件来源**：由什么软件和版本生成，例如 PowerPoint 2024、WPS、Keynote 14、AutoCAD 2023。
3. **测试环境**：操作系统、浏览器及版本，是否在演示站或本地运行。
4. **操作步骤**：从选择文件到看到问题做了哪些操作。
5. **期望结果**：原软件中正确显示的样子。
6. **实际结果**：缺了什么、错在哪里、是否出现警告或报错。
7. **截图或录屏**：最好同时提供原软件和 filens 的对照。
8. **测试文件**：可以公开时附上最小样例；不能公开时说明原因，并尽量制作脱敏版本。

可以直接复制下面的模板：

```markdown
## 文件信息
- 格式：
- 生成软件与版本：
- 文件大小/页数：

## 测试环境
- 操作系统：
- 浏览器与版本：
- filens 版本或提交：

## 复现步骤
1.
2.
3.

## 期望结果

## 实际结果

## 警告或报错

## 附件
- [ ] 对照截图或录屏
- [ ] 可公开的脱敏样例
```

## 关于文件隐私

不要把合同、客户资料、个人信息、密钥或未公开设计直接上传到公开 Issue。优先制作只保留问题元素的最小脱敏样例。如果无法制作样例，截图、文件来源、格式版本、警告信息和清晰的复现步骤同样有帮助。

每一个可复现的真实问题，都会直接帮助 filens 扩大格式覆盖和兼容性。欢迎帮忙试、帮忙挑错，也欢迎提供那些“别的预览器一直打不开”的文件类型线索。
