# Real sample corpus (staged)

This repo vendors multiple upstream projects that contain real-world documents. For regression testing, we stage a curated subset into a single directory with stable filenames.

## What gets staged

The curated list is stored in:

- `tmp/real-samples/real-samples-manifest.json`

It is generated by:

- `npm run generate:real-samples`

Optional expectations overlay (for strict preview regression):

- `tmp/real-samples/real-samples-expectations.json`

The staging script copies every entry into:

- `tmp/real-samples/selected/`

and writes a report to:

- `tmp/real-samples/selected/_meta/stage-report.json`

The staged directory is organized by file extension (e.g. `pptx/`, `docx/`, `xlsx/`).

## Stage the samples

```bash
npm run generate:real-samples
npm run stage:real-samples
```

## Run the CI workflow

This runs the maintained regression chain: generate manifest, verify source files, stage samples, run strict preview, summarize coverage, enforce the coverage gate, and run converted-output e2e.

```bash
node ./scripts/run-real-samples-ci.mjs
```

For a quick command check without launching browsers or converters:

```bash
node ./scripts/run-real-samples-ci.mjs --dry-run
```

For a faster local pass that reuses the current manifest and skips converted-output e2e:

```bash
node ./scripts/run-real-samples-ci.mjs --skip-generate --skip-e2e
```

## Verify the manifest

This checks that every manifest entry points to a non-empty file, sample ids and staged filenames are unique, and strict-preview expectations use known `xfail` reasons without dangling overlay paths.

```bash
npm run verify:real-samples
```

## Run conversion smoke (WASM via Go/wazero)

This runs the manifest-backed OpenXML conversion matrix through `converter-core.wasm` and writes:

- `tmp/real-samples/conversion-report.json`
- `tmp/real-samples/converted/`

```bash
node ./scripts/run-real-sample-conversions.mjs
```

## Run preview smoke (Playwright + demo dist)

This boots a tiny static server for `apps/demo/dist` and uploads each staged file through the demo UI file input.
It writes a JSON report to `tmp/real-samples/preview-report.json`.

```bash
node ./scripts/run-real-sample-preview.mjs
```

Note: the preview smoke includes manifest-backed conversion candidates only if the demo bundle has access to a converter (the demo uses the built-in WASM converter client).

## Summarize preview report

This groups the preview results by extension and coarse failure class.

```bash
node ./scripts/summarize-preview-report.mjs tmp/real-samples/preview-report.json tmp/real-samples/preview-report-summary.json
```

## Summarize corpus coverage

This combines the generated manifest with the strict preview report and writes both machine-readable and human-readable coverage summaries:

- `tmp/real-samples/real-samples-coverage.json`
- `tmp/real-samples/real-samples-coverage.md`

```bash
node ./scripts/summarize-real-sample-coverage.mjs
```

You can then run a CI-friendly coverage gate. By default it requires at least 150 samples, 35 extensions, 7 preview families, 18 conversion candidates, no unexpected strict failures, no xpasses, and no samples skipped by the strict report.

```bash
node ./scripts/verify-real-sample-coverage.mjs
```

Thresholds can be overridden when the corpus intentionally changes:

```bash
node ./scripts/verify-real-sample-coverage.mjs --min-samples 150 --min-extensions 35 --min-families 7 --min-convert 18
```

## Audit available candidates

This scans the vendored real-sample sources, demo samples, and converter fixtures, then compares available files with the current manifest. Use it to find formats or upstream corpora that can expand coverage.

- `tmp/real-samples/real-samples-candidates.json`
- `tmp/real-samples/real-samples-candidates.md`

```bash
node ./scripts/audit-real-sample-candidates.mjs
```

By default the audit focuses on known preview families plus extensions already selected by the manifest. To count every file extension in the source trees, add `--all-extensions`.

## Run strict preview smoke (with expected xfail)

This is like the preview smoke test, but also checks the expected preview family (paged/flow/workbook/etc) and minimal rendered content markers per file extension.
Known unsupported or loader-limited samples should be marked as `xfail` in `tmp/real-samples/real-samples-expectations.json`.
```bash
node ./scripts/run-real-sample-preview-strict.mjs
```

If the strict run discovers new stable failures that should be tracked as `xfail`, you can update the expectations overlay from the strict report:
```bash
node ./scripts/update-expectations-from-strict-report.mjs tmp/real-samples/preview-report-strict.json tmp/real-samples/real-samples-manifest.json tmp/real-samples/real-samples-expectations.json
```

## End-to-end: convert then preview

This runs the manifest-backed conversion batch (Go/wazero + `converter-core.wasm`), stages the converted OpenXML outputs, then runs both preview smoke and strict preview smoke against those outputs.

Artifacts:

- `tmp/real-samples/e2e-report.json`
- `tmp/real-samples/conversion-report.json`
- `tmp/real-samples/converted-manifest.json`
- `tmp/real-samples/selected-converted/`
- `tmp/real-samples/preview-converted-report.json`
- `tmp/real-samples/preview-converted-report-strict.json`

```bash
node ./scripts/run-real-samples-e2e.mjs
```

You can also override paths:

```bash
node ./scripts/stage-real-samples.mjs tmp/real-samples/real-samples-manifest.json tmp/real-samples/selected
```

## Notes

- These samples come from vendored upstream sources under `tmp/real-samples/_sources/` plus the repo's own fixture directories.
- Real `doc`/`docm`/`xls`/`xlsm` conversion samples from Apache POI are checked in under `examples/go-wazero-converter/fixtures/real/apache-poi/`; provenance, license, and formula-coverage details live beside the files.
- `wps`/`et`/`dps` currently use controlled fixtures because no redistributable real sample source has been adopted yet.
- Some upstream corpora (for example, EPUB 3 samples) are stored as unpacked sources and are not staged as `.epub` files by default.
